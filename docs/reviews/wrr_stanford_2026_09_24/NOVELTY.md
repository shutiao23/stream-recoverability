# Novelty 与端到端闭环评估

对应作者提出的第二个问题：idea/design 的新颖度打几分，实验有没有形成能强证明 design 的端到端闭环。

## 1. 把"新颖度"拆成四层来打分

把一篇方法类论文的新颖度笼统打一个分没有意义。审稿人实际上是分四层判断的，而这四层在本文里分数差距很大。

### 1.1 问题的新颖度：8.5 / 10

"记录准入（record admission）该按什么条件筛"这个问题本身是真问题，而且是被整个领域系统性回避的问题。所有人都在优化 gap-filling 的日尺度精度，没有人问"这一年到底该不该进档案库"。文章在 RQ0 里先把代价量化出来（只用观测日算年峰值，MAE 1.305 °C = 1.23 个年际标准差，24.9% 的站年误差超过 1 °C）再提方法，这个顺序是对的，也是最能打动编辑的地方。问题层面没有短板。

### 1.2 洞察（insight）的新颖度：6.5 / 10

核心命题是"筛选规则应该条件在估计量（estimand）所依赖的那部分记录上"。对统计学家来说，这接近于影响函数/支撑集的常识——一个泛函对数据的敏感性由它的支撑决定。所以**原理本身不新**。

真正新的是三件事：(a) 在水文记录准入这个场景里第一次把它写成可证伪的方向性假设；(b) 在 146 个 network / 9 个机构 / 5,114 个完整站年上证明了**反转**（峰值用 timing，年均值用 length），而不是只证明了一边；(c) 反转的方向是**先验预测**的，不是事后解释。(c) 这一点在审稿里价值很高，因为它把"跑了 12 个比较报了赢的那个"这个指控提前挡掉了。

扣分在于：文章把它包装成"二分/反转"，而它其实是**一条带连续参数的定律**（见 REVIEW 主要意见 6）。二分是定律在两个端点上的特例。现在这个包装让洞察看起来像一个经验观察，而不是一条可外推的规律。改成"支撑集上的缺失度量"之后，同样的证据能支撑一个更高的新颖度分数（我估计能到 7.5–8）。

### 1.3 设计（design / 方法）的新颖度：5 / 10

这是全文最弱的一环，而且作者自己在 §5.6 已经诚实承认了：三变量 logistic 回归拿到 59% 的收益，光用 peak overlap 不做任何拟合拿到 57%，conformal 机器只值 0.2 个百分点。也就是说，**"方法"的贡献几乎全部来自换轴，而不是来自模型**。

split conformal + selection-conditional calibration + multiplicative scale 都是标准件。selection-conditional 这一条（先选估计器再标定，避免 winner's curse）写得很好，但那是正确使用已有工具，不是新工具。

文中真正被低估的设计贡献是 §4.7 的 **gate-before-rule**：在拟合任何规则之前，先测量每个动作空间在完美预知下的上界，再和确认集能分辨的最小边际比较，上界低于三倍可分辨边际就不做这个实验。这是一条可以被别的领域直接搬走的实验设计准则，作者却把它当成一个小节写掉了。把它提到方法贡献的位置，设计分能从 5 提到 6.5。

另一个可以立刻做出来的设计贡献是 REVIEW 主要意见 4 提到的**分层筛选（error 与 representativeness 的权衡曲线）**。目前没有人把"质量筛选会把山区站筛掉"这件事做成一条可选择的前沿，这是真正属于 design 的新东西。

### 1.4 证据规模与工程严谨度：9 / 10

9 个国家机构、146 个 network、network 级聚类推断、network 级分层划分、预注册 + 一次性开封、四条 claim 明确报告为不成立、case table 逐字节可复现、正文每个数字由测试套件对着 artifact 校验。这一层远高于 WRR 的平均水平，是这篇稿子最大的资产。

**综合 novelty：6.5 / 10。** 这是一个"问题选得很好、证据做得很硬、方法本身不新、包装低估了自己"的组合。

## 2. 端到端闭环：目前闭在仿真里，没有闭到实践

用一句话回答：**闭环在模拟层面是完整的，在现实层面是断的。**

### 2.1 已经闭合的链条

```
真实记录 → 完整年真值 → 设计断测 → 重建 → 派生统计量误差
        → 筛选决策 → 保留集误差 → 预注册确认集一次性开封
```

这条链上每一环都有实验、有 artifact、有区间、有 clustered 推断。而且还多做了三件多数论文不做的事：先测动作空间上界再决定做不做实验（§4.7）；给对手配一个不可部署的 oracle 重建仍然赢（§5.5）；把全部收益拆到最简单的三变量规则上并诚实报告（§5.6）。**在仿真世界里，这个闭环是合格的，甚至是优秀的。**

### 2.2 断掉的两环

**第一环断在"从未作用于一条真有窟窿的记录"。** 全部 51,524 个 case 都是"完整年 + 人造洞"。你们自己的档案库里有 2,422 个真正不完整的站年（占 7,536 个站年的 32%），它们在论文里只出现过一次——被拿去当"真实断测几何"的采样源，然后就丢掉了。它们恰恰是这条规则要服务的对象。

我实测了一下这一环能产出什么：在近似等保留率下（长度规则 83.2%，timing 规则 81.2%），**两条规则在 15.1% 的真实站年上给出相反的决定**；其中 207 个站年被现行规则接纳、被 timing 规则拒绝（这些是今天正在带着被遮蔽的峰值窗口进入档案库的记录），158 个站年被现行规则拒绝、被 timing 规则接纳（长但避开峰值的断测，被白白丢掉）。这两个整数是整份工作里可操作性最强的数字，而正文里一个都没有。

**第二环断在"下游后果也是仿真的下游"。** §5.9 的 20 °C 超阈误判分析是在同一批合成 case 上算的。所以"下游影响"是仿真的下游，不是档案库的下游。一个 WRR 读者要的是：换了规则之后，区域尺度上"热胁迫站年"的计数变了多少、年峰值的分布变了多少、趋势估计变了多少。

### 2.3 还有一个更隐蔽的断点：主结果的总体（population）不是真实总体

这是 REVIEW 的第一条主要意见。−7.1 个百分点是在 stratified（人造）+ empirical（真实几何）两个 arm 的混合总体上算的，而**在真实几何的 arm 上，确认集的效应是 −0.71 点，95% 区间 (−2.36, +0.05)，包含 0**。也就是说：摘要里那个数字，不是任何一个机构会经历的数字。

好消息是我找到了它为什么是 0，而这个解释本身就是一个水文发现：你们档案库里 6,472 个真实断测中，≥30 天的长断测起始月份显著非均匀（χ² = 44.3，p = 6.5×10⁻⁶），**55.8% 起始于 9 月至次年 1 月，只有 30.7% 起始于 3–7 月**。长断测发生在秋冬——夏季峰值已经被记录完之后。机构的维护和失效日历已经在"意外地"保护夏季峰值了。把这句话写进论文，空结果就从尴尬变成了机制，而且直接把 §6 里那段"维护排期是设计变量"的假设性论证变成了实测。

## 3. 三句话结论

1. 问题选得好，证据做得硬，**方法本身的新颖度撑不起"design 很强"这个说法**——而且作者自己的消融已经证明了这一点，所以不要往方法上加机器，要往**定律化（支撑集连续律）**和**代表性前沿（stratified screening）**上加。
2. 闭环在仿真内完整，在现实端断了两环：**没作用于真实残缺记录，下游后果也是仿真的下游**。补上这两环是从"major revision"走向"accept"的最短路径。
3. 主结果的总体是构造出来的，真实总体上的效应不可分辨。这一点必须在摘要里改口；同时用真实断测季节性把空结果解释掉。做完这一步，论文的诚实度会从"很好"变成"无可指摘"。
