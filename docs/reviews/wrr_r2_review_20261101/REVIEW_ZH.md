**主要意见1，P1：重构时删除了“失败数和错误数必须为零”，应恢复。**

上一版980明确要求目标测试和全库测试的failures、errors均为0。新版本增加了非负整数、非零执行、计数恒等式和JUnit哈希检查，但删除了这条独立条件。新`release_provenance.validate_summary()`同样没有要求这两项为0。

相关位置：[980全库校验第608行](../../../scripts/980_final_release.py#L608)、[980声明测试校验第668行](../../../scripts/980_final_release.py#L668)、[共享校验第82行](../../../scripts/release_provenance.py#L82)。

`passed = tests − failures − errors − skipped`只证明计数自洽，不能证明全部测试通过。例如tests=2、passed=1、failures=1完全满足这个等式。

我使用仓库自己的最小发布fixture，构造包含真实testcase节点的JUnit，并把摘要、JUnit及关联记录加入临时ZIP，同步所有包和验证身份，调用实际`980.accept()`。结果为：

|---|---|---|
| 全库tests=2、passed=1、failures=1，摘要exit_code=0，JUnit也含1项失败 | 拒绝自相矛盾的通过声明 | 接受 |
| 全库tests=2、passed=1、errors=1，摘要exit_code=0 | 拒绝 | 接受 |
| 声明测试tests=2、passed=1、failures=1，摘要exit_code=0 | 拒绝 | 接受 |

正常pytest通常会在有失败时返回非零退出码，但验收器既然负责核验报告，就应该拒绝“退出码0却含失败”的矛盾记录。这个条件上一版已经存在，恢复它不是追加科学门槛。

**次要意见，P2：摘要的“the CDF interval includes zero”没有说明对比量。**

加入经验日历是正确方向，数值与结果表一致。但新句中的CDF没有在摘要里解释，且“CDF interval”容易被读成某个分布函数的区间。实际包含零的是CDF年份选择器相对暖季规则的配对RMSE差区间。

建议明确“选择器”“RMSE差”“配对”，无需在摘要展开方法细节。例如保留前面的warm-season/all-year数值标签，将后半句改为：

> …; for the year-distribution selector, the paired interval for the RMSE difference from warm-season screening includes zero.

这会增加几个词，可从轨迹预算句压缩seed数量等细节。最终以展开后的实际词数为准，不应通过删除区间的对比对象来节省字数。

这属于摘要可读性问题，不是改变CDF结果，不要求重新bootstrap，也不要求改成显著。
