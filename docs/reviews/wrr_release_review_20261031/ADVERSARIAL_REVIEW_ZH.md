**新发现1：摘要的0.06–0.12°C应明确为“绝对变化的中位数”。这是必须修正的统计量标签。**

当前摘要使用`source-recalibrated median 95th-percentile endpoint changes`。保存结果所对应的是各地区、各种子内的`median(abs(delta_q95))`，不是`median(delta_q95)`。重新计算如下：

| 地区/种子 | 有符号端点变化中位数，°C | 端点绝对变化中位数，°C |
|---|---:|---:|
| 瑞士/0 | −0.025623 | 0.069109 |
| 瑞士/1 | −0.116933 | 0.116933 |
| 瑞士/2 | −0.058619 | 0.102356 |
| 巴伐利亚/0 | −0.059112 | 0.060887 |
| 巴伐利亚/1 | +0.008986 | 0.101101 |
| 巴伐利亚/2 | −0.020987 | 0.067049 |

六个有符号中位数中五个为负，因而摘要的正数范围不能按有符号变化理解。正文和图中已经使用绝对变化，这不是原计算错误，而是摘要压缩造成的口径遗漏。[独立复核表](/mnt/lzq-nvme2p4/lzq/stream-recoverability/results/wrr_release_review_20261031/abstract_endpoint_estimands.csv)

建议将该短语改为`source-recalibrated median absolute changes in 95th-percentile endpoints`。保持0.06–0.12°C、三种子、两个地区及不证明收敛的限制不变即可。不要把结果改写成端点统一上移。

验收条件：摘要、正文、图注和表头均指向绝对变化；不需要重新计算轨迹或校准。

**新发现2：建议明确“完整参考年份集合”，避免把它读成连续完整的日历时段。**

摘要中的`for a stated complete period`容易使读者理解为评价时段内每个日历年都存在完整参考。实际评分针对各站预先确定的合格完整参考年份集合。对保存年度输入去除掩膜重复后，41站中有24站的最早与最晚参考年之间存在未进入参考集合的日历年。

例如，`gkd_bayern|11405000`在2010–2025跨度内有7个参考年，其余9个内部日历年不在该集合中。这不是新发现的计算失败：代码使用实际年份计算斜率，没有把不连续年份重新编号。需要澄清的是被恢复和评分的目标范围。[逐站参考年份范围](/mnt/lzq-nvme2p4/lzq/stream-recoverability/results/wrr_release_review_20261031/reference_year_set_scope.csv)

建议将摘要目标改为`the slope over each station's specified set of complete reference years`，并在方法加一句：

> The reference slope is fitted over the eligible complete station-years in the evaluation period; these years need not be contiguous. Artificial gaps and retention rules act on this fixed reference-year set.

若使用符号，可令每站参考集合为Y_i，直接定义其H30对实际日历年份的最小二乘斜率。这样读者不会将已支持的有限集合结果扩大成对所有原始不完整日历年的完整恢复，也不会误读成气候过程趋势。

这是目标定义的文字澄清，不要求重建那些没有完整参考的年份，更不要求改变现有805档案及其评分。
