# 本地逐案例核查材料

`private/wrr_review_case_evidence_20261027/` 是本机的受限工作目录，不是公开归档，也不是可直接发送给审稿人的材料。它含第三方观测的片段及其衍生数值；数据提供方许可和审稿访问方式尚未解决。目录受 `.gitignore` 保护，创建时限制为当前系统用户访问。

在原工作区可执行：

```bash
make review-local-case-audit
```

它从 96 个站点的规范化日值子集重新计算 2,139 个完整参考站年、545 个不完整站年和 35 个源档案见证，并重新核对 2,700 个站年的筛选规则。另用保存的 10 个 USGS 站点日值 API 响应重算 8 个完整参考站年和 9 个见证窗口。它还核算：年度分位数与下界汇总；年度和趋势汇总；逐案例因素分解；20 次源拟合的**已汇总**得分统计；发布规则和配平计数；以及 73,400 条发布状态对应的分母和趋势误差算术。

另有一项独立的年度评分检查：

```bash
make review-private-annual-audit
```

它读取本机保存的 20 次源种子逐案例输出，检查案例键和观测下界，并重新计算各方法的点误差、分布评分、区间评分及同案例配对统计，与保存的汇总结果逐项比较。生成这些输入时使用既有留地区预测并重新应用历史经典方法校准；运行 `make review-private-annual-evidence` 可在原工作区继续整理缺失的种子并执行检查，不覆盖已存在的案例文件。检查结果写入私有目录的 `annual_source_case_audit.json`，其中会明确标出通过或失败以及实际检查的种子数量。20 次种子共享源档案，并非 20 个独立气候或地区。

如需检查候选包中的代码是否足以读取这套本机证据并复算这些结果，可在 Linux 用户、挂载及网络命名空间可用时执行：

```bash
make review-isolated-local-evidence
```

该命令解压本地候选 ZIP，在隔离子进程中隐藏原工作区、禁用网络，并以只读方式显式挂载上述本机证据；先验证项目代码从解压包加载，再运行逐案例审计和 20 次源种子的评分复算。它使用当前安装的 Python 依赖，并非新装环境；证据中仍含未解决权利的第三方衍生数据，不能据此向审稿人发送。汇总报告写入 `results/wrr_review_response_20261027/audit/isolated_private_review_check.json`；不把该报告嵌回自引用的候选 ZIP。若缺少命名空间能力或证据，命令报错，不会退回非隔离模式。

对于后来加入的群组最大误差年度与趋势敏感性，另有：

```bash
make review-isolated-groupmax
```

该检查从候选包解压代码，在无网络的隔离环境中隐藏原工作区，并只读挂载明确列出的本机原始整档案案例缓存、候选来源模型、既有案例证据和必要的处理后输入文件；原缓存与包中共同包含的汇总必须逐文件一致。它从保存的预测重新计算来源群组最大误差、目标年度区间和趋势分布汇总，但不重新训练模型或从提供方原始观测重建排序。输出报告保留在 `results/wrr_review_response_20261027/audit/isolated_groupmax_review_check.json`，不嵌入候选 ZIP；这些本机输入的审稿访问和再分发许可仍待解决。

首次隔离运行还发现，经典随机重建的来源案例依赖一份此前方案未列出的 pre-2010 桥接修正表；原处理函数在该表缺失时会静默跳过。用当前保存的修正表重算后，全部 24 个来源群组最大值单元重现；若省略该表，12 个经典方法单元中有 3 个排序半径改变，主要因为可用来源案例变化，D2 半径不变。此依赖是看到结果后的补充溯源，不是预先冻结的完整来源清单；现在审计会在表缺失或散列不符时失败，并在隔离检查中只读挂载该表。详见 [依赖核查](../../../results/wrr_review_response_20261027/groupmax_annual_calibration/source_repair_dependency.json)与[逐单元影响](../../../results/wrr_review_response_20261027/groupmax_annual_calibration/source_repair_effect.csv)。

进一步重放 20 个历史来源种子，带修正表时保存的 D2 和随机方法分位数均可重现；省略对应修正表时，1,081,252 条种子—案例记录失去完整随机方法分位数，另有 1,018,696 条两次均可用的记录至少一个分位数变化。记录包含重复掩码，不代表独立站年。开放来源整档案的 13 个模式—区域随机方法校准偏移也都受这两张修正表影响；带表重现全部 26 个随机和状态方法偏移集合。原开放来源整档案计划未登记表，后来的单年校准计划已登记。两个入口现在校验对应表的散列，缺失或改变即停止。事后分析不能补成事前注册，亦不等于从原始观测重训。详见[来源种子依赖](../../../results/wrr_review_response_20261027/audit/annual_bridge_repair_dependency.json)和[整档案依赖](../../../results/wrr_review_response_20261027/open_source_sensitivity/archive_bridge_repair_dependency.json)。

另在独立 Python 3.11 环境中使用项目锁文件指定的 NumPy、pandas、scikit-learn 等版本复核：13 个候选来源模型均因内部对象从 scikit-learn 1.2.2 加载到 1.7.2 发出版本警告。所选年度与趋势审计、案例评分和论文包检查能够复现，但这不能证明所有模型或未来版本兼容。另提供与原模型版本一致的[精简复现依赖](../../../requirements-wrr-review-replay.txt)；其范围是上述复现检查，不是完整模型训练环境。[跨版本模型加载核查](../../../results/wrr_review_response_20261027/audit/clean_lock_model_environment.json)、[匹配版本加载核查](../../../results/wrr_review_response_20261027/audit/replay_model_environment.json)。

当前工作区的检查结果为通过：20 个种子合计 2,914,470 条种子—案例记录；逐项比对 3,520 个方法汇总单元和 560 个配对汇总单元（其中方法汇总包含按方法不适用的缺失值）。这些记录包含重复掩码，不代表相同数量的独立站年。

对参考热峰是否已被观测窗口达到的事后分层，原工作区可以运行 `make review-peak-visibility`，从原案例文件生成聚合结果；还可以运行 `make review-peak-visibility-local-audit`，用本机受限案例子集重新计算并逐项核对这些结果。这个分层需要完整参考值，不是预测或发布时可用的诊断，连接群组重采样也不构成独立气候迁移保证。

新斯科舍省旧版核验工作簿另存于 `private/wrr_nova_scotia_verified_20261026/`，其具体再利用条件尚待明确；开放门户的指定子集则按其开放许可和署名条件入包。可在含门户数据的工作区执行 `make review-nova-portal-completeness`；若合法持有旧版工作簿，也可用 `python scripts/590_nova_scotia_portal_audit.py compare --workbooks <本机工作簿目录>` 重新比较。该比较不验证逐点质量、时区或独立传感器准确性。

后续另行冻结的两站探索性遮挡试验将逐案例模型输入和预测保存在 `private/wrr_nova_scotia_exploratory_20261026/`，源模型与这些案例不随公开候选包分发。原工作区可执行 `make review-nova-exploratory-audit`，逐案例重算参考热峰、可见下界、掩码及评分。解压后的候选包可用 `python scripts/599_nova_scotia_exploratory_integrity.py --evidence <本机案例目录> --output <临时报表路径>` 显式指定合法持有的本地案例。该审计不重训模型，不解决严格参考质量或气候独立性。

报告日边界前后移动一小时的事后敏感性，逐案例预测另存 `private/wrr_nova_scotia_clock_sensitivity_20261026/`。原工作区可执行 `make review-nova-clock-audit`；解压后的候选包需要通过 `scripts/606_nova_clock_sensitivity_integrity.py` 的 `--evidence` 和 `--base-evidence` 参数提供本机两套案例，并可用 `--output` 指定临时报表。该核查重新计算参考、掩码和配对评分，但不重训模型或确定真实时区。

这些检查使用源档案中的规范化日值和 USGS 日值 API 响应；前者不是提供方原始文件，后者不包含逐小时传感器数据。USGS 原质量筛选选窗流程已用同一实现重放，但独立算术核查没有独立实现该选窗；这些检查不评估传感器测量误差，不重训预测模型，也不重新生成跨年联合抽样。逐案例评分核查使用保存的预测和重新应用的校准结果，并非从原始数据重新生成预测或检验外尾假设。它们不能证明独立外部参考合格、解决数据权利，或证明整篇论文可以从零复现。

公开候选包包含核查代码但不含本目录的受限数值。若未来取得相应权限并选择合适的审稿访问方式，可以提供双方一致的代码和材料；截至目前没有上传或向外发送。


## 前推地区排除的补充审计（2026-10-26）

核对 98 个种子零模型后，未发现目标测试站或其测试连接群组参与源角色；但原始 before-2010 的 HUC17 估计角色及 NVE 区间校准角色确实含有其他同地区训练群组。因此原前推结果是目标测试群组排除，不能统一称为完整地区排除。历史输出保留原样；严格排除同地区所有群组的事后重训与配对结果见 `results/wrr_review_response_20261027/strict_region_holdout/`。该敏感性只重算两个地区的未来年发布及 HUC17 的 3 站、120 个整档案设置，不能视为全部分析的严格地区重跑。严格模型、逐案例预测与重算中间文件位于 `private/wrr_strict_region_holdout_20261026/`，不随候选包公开。该目录含权利受限衍生数据，不能在未解决许可前作为公共归档。


## 严格地区后续重算与校准支持上界

严格前推的 120 个 HUC17 站点／缺口族／重复设置已接入发布后趋势；原始版本在 1,440 个站年上复现了保存的发布状态，严格版本保留相同掩码、目标真值和可见质量诊断。年度峰值可见性、相同发布数量的分数基准也已配对重算。全部四种源划分的 98 个种子零模型经过全局站点／群组及分类器分组核查。HUC17 前推原始与严格版本的规则校准群组相同，而且模型预测之前可供校准的原始群组最多一个，低于三群组门槛；因此该地区的年度扩张和任务校准仍无支持，而不是证明其校准半径不变。上述结果仍是事后敏感性，未覆盖全部依赖源模型的分析。


## 严格地区的尾部、跨年耦合及压力情景

在完全相同的共同站点重复上，已重算严格地区源模型的年度、两种尾部和三种跨年排序；其中原始 480 条受影响尾部结果和原始总体汇总经逐项复现。报告给出配对均值、覆盖、宽度、区间评分，以及以连接群组为单位的描述性 bootstrap。同步邻站与热相关缺测受影响的 20 个设置合计已经重算，核查掩码、隐藏目标值、邻站隐藏值及原始情景数值。逐案例和模型仍留在 `private/`，汇总位于 `results/wrr_review_response_20261027/strict_region_holdout/`。这些都是已有数据上的事后比较，无法代替独立参考或确认真实缺测机制。

严格 HUC17 模型与校准文件已对全部 456 条受影响年度特征行重新推理，24 个数值字段与此前保存结果逐项一致；这验证现有缓存对应当前模型，但不代替每日模型独立重拟合。压力情景的新缓存凭证绑定模型、校准、输入数据、配置、代码和依赖版本；旧缓存保留在原位置。


## 严格地区模型的群组与删地区敏感性

在 D2 和经典法、原始与严格源模型四方共同可用的站点重复上，复算了连接群组 bootstrap 及逐地区排除结果。原始总体与逐地区汇总均复现；严格前推控制长缺口剔除巴伐利亚后的 MSE 差由负转为小的正值，因此地区排序对本次源模型选择敏感。删地区操作仅重新汇总固定预测，不是重新训练；未把 bootstrap 当作独立气候保证。
